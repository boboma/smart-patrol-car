# V3 部署运维手册

> 面向"换一台电脑/学期初部署/课堂演示前检查"场景的操作手册。
> 功能介绍见根 README，接口定义见《V3-接口协议设计》v1.4，本文只讲"怎么跑起来、出问题怎么查"。

## 一、快速启动（从零到演示，5 分钟）

前置：`D:/anaconda3/python.exe`（依赖已装齐：flask、requests、websockets、paho-mqtt、华为云 SDK、funasr、dashscope）。

```bash
# 终端 A：车队上云（自动拉起 devices.json 里全部未冻结的车）
cd smart-patrol-car\v3-fleet\device
D:/anaconda3/python.exe start_fleet.py

# 终端 B：业务后端（REST :8000 + WS 广播 :8889 + AI 服务）
cd smart-patrol-car\v3-fleet\server
D:/anaconda3/python.exe app.py
```

然后浏览器**双击直开**（无需任何 web 服务器）：

| 页面 | 文件 | 用途 |
|---|---|---|
| 测试台 | `v3-fleet\web\test_console.html` | 选车/手控/AI 语音控车/接口调试 |
| 监控回放 | `v3-fleet\web\fleet_view.html` | 多车同屏 + 轨迹回放（演示主页面） |
| 管理后台 | `v3-fleet\web\admin.html` | 总览/设备注册冻结/命令历史（admin/admin123） |

**就绪信号**：后端启动横幅列出全部接口、`http://127.0.0.1:8000/health` 返回 `online>0`。
AI 语音首次使用前 FunASR 需预热约 30 秒（后台自动，预热完成前发语音会等它加载完才返回）。

## 三、AI 服务部署矩阵（按现场条件选）

`server/config.json` → `ai.asr_provider` 切换（改后重启后端）：

| | `"local"`（FunASR 本地） | `"qwen"`（云端 asr-flash-message） |
|---|---|---|
| 需要安装 | funasr + torch + kaldi-native-fbank + 2.1G 模型缓存 | **仅 dashscope（纯 Python 包，秒装）** |
| 首次启动 | 模型加载约 30 秒（后台预热） | 即时 |
| 断网可用 | ✅ | ❌（依赖中转站网络与额度） |
| 适用 | 演示机/主讲了（不翻车） | 学生机/临时环境（现场装 FunASR 太慢时） |

- LLM（文字→指令解析）固定走 `ai.llm_*`（DeepSeek），两个 provider 都需要它。
- **模型缓存位置**：`D:\model_cache\modelscope`（用户级环境变量 `MODELSCOPE_CACHE` 指向它）。
  换机器迁移 = 拷贝这个目录 + 设同名环境变量，不用重新下载。
- 若只改配置文件里的 key（`ai.*`），重启后端生效；代码不用动。

## 四、数据与日志维护

| 文件 | 说明 | 维护 |
|---|---|---|
| `server/track.db` | SQLite 轨迹库（WAL 模式，可能看到 track.db-wal 伴生文件，属正常） | 自动治理：7 天过期 + 单车 2 万条上限，后端启动时清理；手动：`python track_store.py stats`（看各车行数）/ `python track_store.py clean`（立即清理） |
| `server/commands.log` | 命令审计（含 AI 指令与拒绝记录，每条带 device_id） | 追加式，无需维护；管理后台"命令历史"页可视化 |
| `server/devices.json` | 设备注册表 | 管理后台维护为主；手工编辑后重启后端生效 |
| `server/devices_secret.json` | 设备接入密钥 | **敏感，仅本机**；丢失 = 该车无法用 run_car.py 启动，需在管理后台重新注册 |

## 五、FAQ / 踩坑清单（实战踩出来的，按症状查）

**1. 网页按"执行命令"报 `TypeError: Failed to fetch`，但 GET 都正常**
→ CORS 预检被拦。后端已带三件套（Allow-Origin/Allow-Headers/Allow-Methods），若自写新接口页面仍报，
检查是不是引入了新的自定义请求头（如 `X-Admin-Token`）——自定义头的 GET 也走预检。

**2. 模拟车反复"连上又掉线"**
→ 同 device_id 的另一份模拟器还在跑（任何版本目录下）。MQTT 鉴权 clientId 精确到小时，
同一小时内两次启动 clientId 相同，新连接踢旧连接。全局搜 python 进程清理干净再启动。

**3. 后端启动后 `/ai/asr` 长时间无响应**
→ FunASR 首次加载模型（约 30 秒，属正常）；若远超 1 分钟，看后端日志是否在"Downloading"——
说明 `MODELSCOPE_CACHE` 环境变量没生效、在重新下载模型。新开终端或显式设置后重启。

**4. 本机其他项目报 numpy / pydantic 版本警告**
→ 安装 funasr 把 numpy 降到 1.23.5（torch 2.0 要求）、dashscope 把 pydantic 降到 2.5.2 所致。
不影响 V3 运行；其他项目冲突时用独立 venv 隔离。

**5. `python app.py` 报 8000 端口占用**
→ 上次的后端没退干净。任务管理器搜 python，或
`Get-CimInstance Win32_Process -Filter "Name like 'python%'"` 找到 PID 后 `Stop-Process -Id <pid>`。

**6. 换电脑部署的最小清单**
→ ①装 Anaconda 并 `pip install flask requests websockets paho-mqtt`（+ 按第三节选 AI 依赖）；
②装华为云 SDK 并打上两个补丁（cache.py shim + IamHelper import，见 V2 app.py 头注释）；
③拷贝整个 `smart-patrol-car/`（含两个 config.json 与 devices_secret.json，这些不入仓）；
④AI 用 local 路线再拷 `D:\model_cache\modelscope` 并设环境变量。
