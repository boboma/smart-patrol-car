## 1. 六端角色与链路总览

| 编号 | 链路 | 协议 | 交互模式 | 说明 |
|---|---|---|---|---|
| L1 | APP ↔ 业务后端 | HTTP（端口 8000，明文） | 请求/响应 | 车列表、单车状态轮询、控制命令 |
| L2 | 业务后端 ↔ 华为云 IoTDA | HTTPS（应用侧 SDK，AK/SK 签名） | 请求/响应（拉模式） | 查影子、查设备状态、下发命令、注册/冻结设备 |
| L3 | 小车端 ↔ 华为云 IoTDA | MQTT over TLS（8883） | 双向 | 属性上报（上）/ 命令与回执（下） |
| L4 | 网页端 ↔ 业务后端 | **WebSocket（`ws://<host>:8889/ws`）** + HTTP 轮询兜底（:8000） | 推送为主 | 车队状态广播、轨迹回放 |
| L5 | 业务后端内部 | — | — | 设备注册表 devices.json、密钥 devices_secret.json、审计日志 commands.log、SQLite track.db（**非外部链路，架构图不画连线**） |
| **L6** | **Admin 管理端 ↔ 业务后端** | **HTTP（端口 8000，`/admin/*`）** | 请求/响应（带 `X-Admin-Token`） | 登录、设备注册/冻结、命令历史、车队总览（第 13 节） |
| **L7** | **AI 模块 ↔ 业务后端** | **HTTP（端口 8000，`/ai/*`）** | 请求/响应 | 语音转文字、自然语言控车（第 16 节，v1.4 新增） |

> 编号说明：L5 已占用为「业务后端内部」，故新增管理端链路顺延编号 **L6**，不重排既有编号；步骤⑦ AI 链路顺延编号 **L7**（v1.1~v1.3 期间为规划占位，v1.4 起正式定义）。

链路走向（一图流，v1.4 更新）：

```
Admin 管理端(web/admin.html) ──L6 HTTP /admin/*──> ┐
APP(鸿蒙 CarCtrlFleet) ──L1 HTTP :8000──────────> ├─> 业务后端(Flask:8000 + WS:8889) ──L2 HTTPS──> 华为云IoTDA <──L3 MQTT── 小车端(模拟/真车)
HTML 视图端(fleet_view.html) ──L4 WS:8889/HTTP──> ┘         │                                   (含设备注册/冻结类调用)
test_console.html AI 卡 ──L7 HTTP /ai/*─────────> ┘         └──L7──> AI 服务(ai_service.py：FunASR 本地 / qwen 云端 + DeepSeek LLM)
```

**端口清单**：8000 = Flask REST（业务接口 + /admin/*）；8889 = WebSocket 广播（独立端口，Flask WSGI 同步模型不支持长连接，见 `server/ws_server.py` 头注释）；8883 = 设备侧 MQTT over TLS。

## 2. 通用约定

| 项 | 约定 |
|---|---|
| device_id 格式 | 华为云格式 `{product_id}_{node_id}`，如 `6ae440347f2e6c302fa846ee_car_001` |
| 响应包络 | 成功：`{"ok": true, ...数据}`；失败：`{"ok": false, "error": "原因"}` + 对应 HTTP 状态码 |
| 状态字段 | `x`, `y`（坐标，米）、`heading`（角度，0=正上，顺时针）、`speed`（0~100）、`battery`（0~100）、`time`（影子事件时间） |
| 坐标系 | 沿用 V2 物模型（smart-car-model.json），真车接入后字段不变 |
| 时间 | 沿用影子 `event_time`（UTC，yyyymmddHHMMSS 格式） |

## 3. 设备注册表（L5，业务后端本地）

V3 阶段用静态配置文件 `devices.json`（V2 是 config.json 写死单台，这是第一个升级点）：

```json
{
  "devices": [
    { "device_id": "6ae440347f2e6c302fa846ee_car_001", "name": "1号巡检车", "color": "#e24b4a", "frozen": false },
    { "device_id": "6ae440347f2e6c302fa846ee_car_002", "name": "2号巡检车", "color": "#185fa5", "frozen": false }
  ]
}
```

- ~~动态注册/冻结设备属于管理后台阶段（开发顺序第 5 步），届时接口另行追加~~ **已于 v1.2 兑现：见第 13 节 `/admin/*` 接口**
- `color` 供网页端多车分轨渲染用
- `frozen`（v1.2 新增）：`true` 表示设备已冻结——云侧已 FreezeDevice（设备无法再连 MQTT）且业务后端拒绝对其下发命令（400）。该字段可缺省，缺省视为 `false`（v1.0/v1.1 的注册表文件向后兼容）；由 `/admin/devices/<id>/freeze|unfreeze` 维护
- **配套密钥文件 `devices_secret.json`（v1.2 新增，不入仓）**：与注册表同目录，结构 `{"secrets": {device_id: 密钥}}`。管理后台注册设备时生成密钥写入此处（云侧/本地各存一份），设备端 `run_car.py` 从这里读取。**该文件是敏感凭证，仅存本机，严禁提交仓库、严禁在 README/文档中记录任何密钥内容**

## 4. L1：APP ↔ 业务后端（HTTP）

### 4.1 `GET /devices` — 车列表（APP 选车页用）【新增】

响应示例：
```json
{
  "ok": true,
  "devices": [
    { "device_id": "6ae..._car_001", "name": "1号巡检车", "online": true,  "battery": 95, "frozen": false },
    { "device_id": "6ae..._car_002", "name": "2号巡检车", "online": false, "battery": null, "frozen": false }
  ]
}
```
（battery 供 APP 选车页展示；离线车取影子中最后一次上报值，从未上报过为 null。`frozen` 为 v1.2 超集字段，按 v1.0 最小集消费的客户端不受影响）

### 4.2 `GET /status?device_id={id}` — 单车状态（APP 控制页轮询）【升级：device_id 必填】

响应示例：
```json
{
  "ok": true,
  "device_id": "6ae..._car_001",
  "online": true,
  "x": 1.2, "y": 3.4, "heading": 90,
  "speed": 80, "battery": 95, "time": "20261105T210000Z"
}
```

### 4.3 `POST /command` — 控制命令【升级：device_id 必填】

请求：
```json
{ "device_id": "6ae..._car_001", "cmd": "FORWARD", "speed": 80 }
```
- `cmd` ∈ FORWARD / BACK / LEFT / RIGHT / STOP（白名单不变）
- `speed` 仅 FORWARD / BACK 需要，0~100 整数
- 同步命令：等小车执行回执才返回（超时约 20 秒）

响应：
```json
{ "ok": true, "device_id": "6ae..._car_001", "command_id": "...", "executed": true, "response_name": "FORWARD" }
```

### 4.4 `GET /health` — 探活【升级：返回车队摘要】

响应：`{ "ok": true, "total": 2, "online": 1 }`

### 4.5 错误码约定

| HTTP | 场景 |
|---|---|
| 400 | 参数错误：缺 device_id / device_id 未注册 / 未知 cmd / speed 越界 |
| 502 | 华为云 API 调用失败 |
| 504 | 命令下发超时未收到回执 |

## 5. L2：业务后端 → 华为云 IoTDA（HTTPS，应用侧 SDK）

| 操作 | SDK API | 关键参数 | 说明 |
|---|---|---|---|
| 查单车影子 | ShowDeviceShadow | device_id | 位置/状态数据源 |
| 查设备在线状态 | ShowDevice | device_id | ONLINE / OFFLINE / INACTIVE |
| 下发命令 | CreateCommand | device_id、service_id="car"、command_name、paras | paras 恒非空（无参传 `{}`，V2 已踩坑） |
| 注册设备（v1.3 补录） | AddDevice | node_id、device_name、product_id、auth_info(secret) | 由 L6 `/admin/devices` 触发；不带 device_id 时平台按 `{product_id}_{node_id}` 自动拼接，与本地注册表规则天然对齐 |
| 冻结设备（v1.3 补录） | FreezeDevice | device_id | 由 L6 `/admin/devices/<id>/freeze` 触发；云侧真正禁连 MQTT |
| 解冻设备（v1.3 补录） | UnfreezeDevice | device_id | 由 L6 `/admin/devices/<id>/unfreeze` 触发 |

- 云侧**天然按 device_id 路由，V3 零改动**，只是调用来源从"config 写死一台"变成"按请求参数路由"；v1.2 起调用来源又多了管理端（注册/冻结），但走的仍是同一套应用侧 SDK 客户端
- V3 保持拉模式（后端定时查影子）；后续如需更实时，可切换为**应用侧推送**（见下方说明），接口不变、内部实现升级

**推送模式升级路径说明（重要，勿与设备 MQTT 混淆）**：
- 设备侧 MQTT(8883) 是**设备专用通道**，业务后端不能冒充设备去连
- 华为云应用侧的正确推送通道有两种：① **AMQP 消息队列**（后端用 AMQP SDK 长连接，实时收设备属性/状态变化，官方推荐的轮询替代方案）；② **订阅推送**（在 IoTDA 控制台注册回调 URL，平台主动 HTTPS POST 到后端）
- 收益：消除轮询 API 调用；数据到达即达网页广播，不再等轮询间隔
- 注意：设备 5 秒上报节奏不变，实时性天花板仍由设备上报频率决定（再快就吃消息额度）

## 6. L3：小车端 ↔ 华为云 IoTDA（MQTT）

沿 V2 全套协议，唯一变化是一台真实的设备端对应一个 device_id（模拟阶段 = 一个 car_mqtt_client 进程实例）：

| 方向 | 主题 | 载荷 |
|---|---|---|
| 上行·属性报告 | `$oc/devices/{device_id}/sys/properties/report` | `{"services":[{"service_id":"car","properties":{"x":..,"y":..,"heading":..,"speed":..,"battery":..}}]}` |
| 下行·命令 | `$oc/devices/{device_id}/sys/commands/#`（qos1） | 平台下发，含 command_name + paras |
| 上行·命令回执 | `$oc/devices/{device_id}/sys/commands/response/request_id={id}` | result + response_name |

- 鉴权：`clientId = {device_id}_0_1_{timestamp}`，`password = hmacsha256(密钥=UTC时间戳, 内容=secret)`（沿用 V2）
- 上报节奏：运动 5 秒 / 空闲 60 秒（沿用 V2，保护每日消息额度；车队版是额度优化重点，多车可再合包）

## 7. L4：网页端 ↔ 业务后端

### 7.1 主通道：`WebSocket /ws`【步骤④ 已实现，复用 V1 技术】

**实现落地（v1.3 补录，2026-11-07）**：v1.0 只约定路径 `/ws` 与帧格式，未规定端口。实际实现为 `ws://<host>:8889/ws`（独立端口），由 `server/ws_server.py` 用 `websockets 15.x` + asyncio 事件循环在 daemon 线程中运行，随 `app.py` 启动；广播帧额外带 `color` 超集字段（来自 devices.json，供网页分轨渲染，前端零额外请求），按 v1.0 最小集消费的客户端不受影响。

- 网页连接后，服务端**每 1 秒广播一帧**车队状态（数据源为后端车队状态缓存 `fleet_cache`）：
```json
{
  "type": "fleet_state",
  "ts": "2026-11-05T21:00:00",
  "cars": [
    { "device_id": "6ae..._car_001", "name": "1号巡检车", "online": true,
      "x": 1.2, "y": 3.4, "heading": 90, "speed": 80, "battery": 95, "time": "..." },
    { "device_id": "6ae..._car_002", "name": "2号巡检车", "online": false, "x": null, "y": null }
  ]
}
```
- 心跳：客户端每 30 秒发 `{"type":"ping"}`，服务端回 `{"type":"pong"}`
- 断线自动重连：前端指数退避（V1 car_view 已实现，直接复用）
- 设计理由：一次广播覆盖全部车，请求数不随车数增长；网页本地按 device_id 分轨渲染 + 前端筛选显示哪几辆

### 7.2 兜底通道：`GET /fleet/status`【新增】

WebSocket 不可用时（或调试用）HTTP 拉取，响应即 `fleet_state` 中的 `cars` 数组。

### 7.3 轨迹回放：`GET /track?device_id={id}&from={t1}&to={t2}`【新增，开发顺序第 3 步实现】

响应：
```json
{ "ok": true, "device_id": "...", "count": 97,
  "points": [ {"x":.., "y":.., "t": "2026-11-06 20:30:00", "heading": 90, "speed": 50} ] }
```
数据源为后端 SQLite 轨迹表（挂在车队状态缓存刷新处，**状态有变化才插行**——空闲 60s 的重复上报不产生重复点，见第 12 节勘误）。

补充约定（v1.1 补录）：
- `from`/`to` 可省略（缺省最近 24 小时），格式接受 `"YYYY-MM-DD HH:MM[:SS]"`（本地时间）或 Unix 秒；格式非法返回 400
- `t` 为本地时间 `YYYY-MM-DD HH:MM:SS`（与第 2 节影子的 UTC event_time 格式不同，属有意设计：轨迹给人看/回放用，可读优先）
- `heading`/`speed`/`count` 为**超集字段**：回放动画需要朝向摆车与节奏；按本节最小集 `{x,y,t}` 消费的客户端不受影响
- 未注册 device_id → 400

## 8. 设计决策（V3 先按此执行，可讨论）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 控制冲突不设锁：多端同时控一辆车，最后者生效 | 实现简单；commands.log 已记录 device_id 可审计；车队规模小，冲突概率低 |
| D2 | APP 记住"上次绑定的车"用端侧本地存储（Preferences），不进接口协议 | 绑定是单机偏好，不是共享状态 |
| D3 | 网页端实时性上限 = 设备上报节奏（运动 5s） | 数据源决定；要缩短需提高设备上报频率（吃消息额度）。后端将来可换应用侧推送（AMQP）加速"到网页"的链路，接口已按"数据来源可替换"设计，届时 APP/网页零改动 |
| D4 | 通信维持 HTTP 明文，不上 HTTPS | 教学/局域网场景，配证书收益低 |
| D5 | 设备注册表 V3 静态 JSON，动态管理留给第 5 步管理后台 | 先跑通链路，再上管理面（**v1.2 已兑现：第 13 节 `/admin/*` 提供动态注册/冻结**） |

## 11. 补充说明：应用侧推送通道的完整认知（2026-11-05 讨论补录）

**背景**：第 5 节的推送升级路径需要修正补充。控制台"接入信息"显示**应用侧有三种接入协议**：HTTPS(443)、AMQPS(5671)、**MQTTS(8883)**——应用侧确实存在合法的 MQTT 通道。注意它与设备侧 MQTTS(8883) **端口相同但域名不同**（`iotda-app` vs `iotda-device`），是两套独立域名和鉴权体系，不可混用。

### 应用侧三种推送通道对比

| 维度 | AMQP 推送 | 应用侧 MQTT 转发 | HTTPS 订阅推送 |
|---|---|---|---|
| 模型 | 队列：平台写入应用专属队列，后端消费 | 发布/订阅：平台推到指定 Topic，后端订阅 | 回调：平台 POST 到后端公网 URL |
| 可靠性 | 消费确认（ack），不丢 | QoS 0 尽力而为 | HTTP 响应确认 |
| 离线补偿 | 队列积压，回来接着消费 | 未建链仅保留 24h 内且 <1GB 数据，超期清空 | 无（推送失败即丢） |
| 前置配置 | 规则引擎建订阅规则 → 转发到 AMQP 队列 | 规则引擎建订阅规则 → 转发到自定义 Topic | 规则引擎建订阅规则 → 指定回调 URL |
| Python 生态 | qpid-proton（官方有 demo） | paho-mqtt（设备端模拟器同库） | Flask 直接接 |
| 限制 | — | 流控参考连接规格 | 800 TPS，不建议大流量 |

**共同前提**：三种通道都必须先在 IoTDA **规则引擎**创建订阅规则（指定数据类型 + 转发目标），规则未配则平台不推任何数据。

### 本项目结论

- **共同点不变**：三种通道都只替换"喂缓存的动作"，L1/L4 接口与网页/APP 零改动（见 D3）。
- **选型策略**：真到推送升级时，先试**应用侧 MQTT 转发**（paho-mqtt 与设备端代码同库，开发最快）；若可靠性或额度成为瓶颈，再切 **AMQP**（官方推荐、不丢数据）。以 V3 体量两者均绰绰有余。
- **实时性天花板不变**：设备 5 秒上报节奏是数据新鲜度的根源，通道切换只优化"数据到网页的速度"。

## 13. 管理后台接口（/admin/*，v1.2 新增，开发顺序第 5 步）

### 13.1 通用约定

| 项 | 约定 |
|---|---|
| 鉴权 | 登录接口 `POST /admin/login` 签发 token（`secrets.token_hex(16)`，**只存后端内存，重启全部失效**）；此后所有 `/admin/*` 请求（login 除外）必须带请求头 `X-Admin-Token: <token>`，无效/缺失返回 401 |

### 13.2 `POST /admin/login` — 登录

请求：
```json
{ "username": "admin", "password": "admin123" }
```

成功响应：`{ "ok": true, "token": "3f9a..." }`
失败：401 `{"ok": false, "error": "用户名或密码错误"}`

### 13.3 `GET /admin/devices` — 设备管理列表

响应示例：
```json
{ "ok": true, "devices": [
  { "device_id": "6ae..._car_001", "name": "1号巡检车", "color": "#e24b4a",
    "frozen": false, "online": true, "battery": 95 }
]}
```
（online/battery 读车队缓存快照，口径与 GET /devices 一致）

### 13.4 `POST /admin/devices` — 注册新设备

请求：
```json
{ "node_id": "car_003", "name": "3号巡检车", "color": "#7a4be2" }
```
- `node_id`：3~32 位字母/数字/下划线
- 完整 `device_id = {product_id}_{node_id}`（product_id 取 config.json 的 `product_id` 字段）
- `color`：`#RRGGBB`

处理流程（任一步失败不落半截状态）：
① 参数校验与 device_id 查重（重复 400）→ ② 生成 16 位随机密钥 →
③ 调华为云 add_device 真正注册（失败 502）→ ④ 密钥写 `devices_secret.json`（不入仓）→
⑤ 设备记录（含 `frozen:false`）写 `devices.json` → ⑥ 刷新车队缓存与 WS 广播清单

成功响应（**密钥只此一次返回**，前端醒目展示一次，之后任何接口都不再回显）：
```json
{ "ok": true, "device_id": "6ae..._car_003", "secret": "xK3mP9qR7tW2vY5z" }
```

错误码：400 参数非法 / node_id 与既有设备撞名；401 未登录；502 云侧注册失败

### 13.5 `POST /admin/devices/<device_id>/freeze` 与 `/unfreeze` — 冻结/解冻

流程：先调云侧 FreezeDevice / UnfreezeDevice（设备真正无法再连 MQTT），成功后才写回 devices.json 的 `frozen` 字段（顺序保证"本地 frozen=true"永真）。幂等：状态没变不重复调云。

响应示例：
```json
{ "ok": true, "device_id": "6ae..._car_003", "frozen": true, "before": false }
```

错误码：400 未注册 device_id；401 未登录；502 云侧操作失败

联动约束：`frozen=true` 的设备，`POST /command` 直接 400 `{"ok": false, "error": "设备已冻结，命令已拒绝"}`（拒绝动作记入 commands.log 审计）。

### 13.6 `GET /admin/commands?limit=50` — 命令历史

commands.log 的结构化解析（最新在前；limit 默认 50、上限 500）：
```json
{ "ok": true, "items": [
  { "time": "2026-11-07 10:38:41", "device_id": "6ae..._car_002", "cmd": "RIGHT",
    "paras": {}, "status": "已执行", "detail": "RIGHT" },
  { "time": "2026-11-06 19:37:21", "device_id": "000..._car_999", "cmd": "FORWARD",
    "paras": {}, "status": "已拒绝", "detail": "device_id 未注册: 000..._car_999" }
]}
```
- `status` ∈ 已执行 / 已下发 / 无回执 / 已拒绝 / 下发失败
- "下发→回执"按 device_id+cmd 配对成一条；配不上回执的记"无回执"
- 含命令关键字但细节解析失败的行整行放进 `raw` 字段（不丢数据）；commands.log 不存在或为空返回 `{"ok": true, "items": []}`

### 13.7 `GET /admin/overview` — 车队总览

响应示例：
```json
{ "ok": true,
  "total": 3, "online": 2, "offline": 1, "frozen": 0,
  "battery_rank": [
    { "device_id": "6ae..._car_001", "name": "1号巡检车", "battery": 95 },
    { "device_id": "6ae..._car_003", "name": "3号巡检车", "battery": null }
  ],
  "messages_today": 1284,
  "messages_by_day": [ { "day": "2026-11-01", "count": 0 }, ... ]
}
```
- `battery_rank` 按电量降序，null（从未上报）排最后
- 消息量统计口径：**track_points 落库行数 ≈ 上报帧数 ≈ 消息额度消耗的近似值**（"变化才记"导致低估，是额度监控的安全侧），用于 S0 每日约 1 万条额度的监控打底

## 16. L7：AI 接口（/ai/*，v1.4 新增，步骤⑦）

> 实现：`server/ai_service.py`（ASR + LLM 解析）+ `server/app.py` 两个端点；网页入口：`web/test_console.html` AI 语音控车卡

### 16.1 设计原则与边界

**AI 负责听懂，后端负责只允许安全的事发生。** LLM 只做"翻译"（话术 → 结构化指令），产出必须经白名单校验（16.4）后，走与手控 `POST /command` **完全相同**的下发链路（`dispatch_command`）——冻结拦截、审计日志（commands.log）、回执后立即刷缓存对 AI 指令自然生效。LLM 输出永远不可信，白名单是最后一道闸。

- **不改变 L1~L6 任何既有接口**，只新增 `/ai/*` 命名空间
- ASR 双提供方：`local`（FunASR 本地推理，断网可用）与 `qwen`（云端 qwen-audio-3.1-asr-flash-message，走 dashscope WebSocket 协议），由 config.json `ai.asr_provider` 切换，**改后需重启后端生效**（不热切换）
- LLM：DeepSeek `chat/completions`（temperature=0，max_tokens=300），凭证只存 config.json 的 `ai` 段，不入仓

### 16.2 `POST /ai/asr` — 语音转文字

请求：

```
POST /ai/asr
Content-Type: audio/wav
Body: 完整 WAV 文件的原始字节（16kHz / 单声道 / 16bit 为推荐配置）

# 或裸 PCM 流（按 query 参数补 WAV 头）：
POST /ai/asr?rate=16000&channels=1&bits=16
Content-Type: audio/pcm
Body: PCM 字节
```

响应：
```json
{ "ok": true, "text": "1号车前进速度60", "provider": "local" }
```

错误码：400 请求体为空 / rate 等参数非整数；502 ASR 失败（模型未就绪、云侧失败、音频损坏等——属服务端依赖故障，调用方改参数解决不了）

### 16.3 `POST /ai/command` — 自然语言控车

请求：
```json
{ "text": "1号车前进速度60然后左转", "device_id": "6ae..._car_001" }
```
- `text` 必填：要解析的中文指令
- `device_id` 可选：**"页面上已绑定哪台车就控哪台"语义**——带它时 LLM 解析出的车号被忽略（UI 选中的车优先，避免"看着 A 车卡片说话结果 B 车动了"）；必须已注册，否则 400

LLM 输出格式（内部约定，教学参考）：
```json
{ "car_node": "car_001 或 \"\"（未指明车时留空）",
  "actions": [ {"cmd": "FORWARD", "speed": 60}, {"cmd": "LEFT", "speed": null} ],
  "reply": "好的，1号车前进然后左转" }
```
（FORWARD/BACK 必须带 speed，用户没说默认 50；STOP/LEFT/RIGHT 的 speed 为 null；actions 按话语顺序；"1号车/一号车"→car_001，以此类推）

成功响应（`actions` 与 `results` 按下标一一对应，逐条独立执行、独立记结果）：
```json
{ "ok": true,
  "text": "1号车前进速度60然后左转",
  "reply": "好的，1号车前进然后左转",
  "car": { "device_id": "6ae..._car_001", "name": "1号巡检车" },
  "actions": [ {"cmd": "FORWARD", "speed": 60}, {"cmd": "LEFT", "speed": null} ],
  "results": [ {"cmd": "FORWARD", "speed": 60, "ok": true, "executed": true, "detail": "FORWARD"},
               {"cmd": "LEFT",   "speed": null, "ok": true, "executed": true, "detail": "LEFT"} ] }
```

错误码：

| HTTP | 场景 |
|---|---|
| 400 | text 为空 / device_id 未注册 / 白名单校验后无合法动作（"没有可执行的有效指令"）/ 没找到车 / **指令与选中项都没指明车** |
| 502 | LLM 调用失败（网络/HTTP 错误）或两轮重试后输出仍非合法 JSON（"AI 解析失败"） |

单条动作执行失败（冻结 400 / 云失败 502 / 无回执 504）**不是**整体 HTTP 错误：记入对应 `results[i]`（`ok:false` + `detail` 原因），其余动作继续，部分成功也如实返回。

### 16.4 白名单校验规则（协议强约束）

LLM 产出经 `validate_actions` 过滤后才可执行：

| 规则 | 内容 |
|---|---|
| cmd 白名单 | 必须 ∈ FORWARD / BACK / LEFT / RIGHT / STOP，白名单外**丢弃并记录** |
| speed 校验 | FORWARD/BACK 必须 0~100 整数（bool 拦截：Python 中 `True` 是 `int` 子类，不拦会被当 1 混过校验）；STOP/LEFT/RIGHT 忽略 speed |
| 数量上限 | 1~6 条，超出部分视为解析噪音丢弃；**全部非法**则 400"没有可执行的有效指令" |
| car_node | 必须在注册表 node_id 集合内，否则 400"没有找到车：xxx" |

### 16.5 ASR provider 配置切换

config.json `ai` 段：

```json
"ai": {
  "asr_provider": "local",
  "asr_base_url": "...", "asr_api_key": "...", "asr_model": "...",
  "llm_base_url": "https://api.deepseek.com", "llm_api_key": "...", "llm_model": "deepseek-flash"
}
```

- `local`：FunASR 本地推理（paraformer-zh + fsmn-vad + ct-punc，模型缓存在本机，首次加载约 30 秒后常驻内存；后端启动时后台预热，断网可用）
- `qwen`：云端识别（dashscope SDK Recognition 类，WebSocket 端点 `/api-ws/v1/inference`——该模型不走 OpenAI 兼容 HTTP，传音频会 400 url error）
- 切换方法：改 `asr_provider` 后**重启后端**（provider 在进程启动时读定，不热切换）；`/ai/asr` 响应的 `provider` 字段可确认当前生效方
