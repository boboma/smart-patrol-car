〇、开始前：先搞懂华为云的账号体系

新手最容易懵的不是页面操作，而是"账号、用户、密钥"这几个词。先花三分钟建立概念地图，后面所有操作都会顺理成章。

0.1 四个关键角色

概念是什么本项目中的例子
主账号（账号 / domain）注册华为云时创建的，一个手机号一个主账号，拥有全部权限、全部资源、全部费用。账号名可能是 hid_xxxx 开头（新一代账号体系）。hid_0d1u65...*
IAM 子用户（用户）主账号下创建的"员工账号"，避免把主账号密码和密钥交给别人。子用户被加进某个用户组，用户组挂权限策略（如 admin 管理员、只读）。iot-aa、iotda-teacher、iotda-t2
IoTDA 实例物联网平台的"一套运行环境"。免费的标准版单元 S0：1000 台设备、每日 1 万条消息。每个实例有专属接入域名（前后两串字符都是实例标识）。实例 ID 71b55ab7e9
项目（project）华为云按区域划分的资源容器，北京四区域对应一个 project_id。调 API 时必须带上。01a18ad51bfd...

0.2 密码与密钥的区别（新手必读）

凭证用途谁在用本项目需要吗
登录密码登录华为云控制台网页用（人用）人教师登录控制台需要；程序不需要
AK / SK
（访问密钥 Access Key）		程序调华为云 API 时的身份凭证（机器用）。AK 是公开ID，SK 是私钥，SK 只在创建时显示一次业务后端 app.py必须
设备密钥（secret）设备（小车）连平台时算 MQTT 签名用，一机一密小车端 car_mqtt_client.py必须
一句话记住密码管"人进网页"，AK/SK 管"程序调 API"，设备密钥管"设备连云"。三者互不通用，丢了都要重新生成。

0.3 本项目的三层结构与凭证分布

鸿蒙 APP（应用端）      —— 不持有任何华为云凭证，只认业务后端地址
   │ HTTP
业务后端 app.py          —— 持有 AK/SK + project_id + 应用侧端点（config.json）
   │ HTTPS + 签名
华为云 IoTDA 实例         —— 域名里隐含实例 ID
   │ MQTT/TLS + 设备密钥签名
小车端 car_mqtt_client.py —— 持有设备ID + 设备密钥 + 设备侧域名

一、基础操作流程：从零到设备上云

完整走一遍约 40 分钟（不含注册实名）。每一步末尾有"✅ 自检"，做了就勾。

1.1 注册与实名认证

1
注册华为云账号 访问 https://www.huaweicloud.com → 右上角"注册" → 手机号 + 验证码。注册完你就是主账号。
2
个人实名认证 控制台右上角头像 → 账号中心 → 实名认证 → 选"个人认证"，用银行卡或人脸方式（几分钟生效）。不做实名无法开通 IoTDA 免费实例。
✅ 自检控制台右上角能正常进入"账号中心"，实名认证状态显示"已认证"。

1.2 开通 IoTDA 标准版免费实例

3
进入 IoTDA 服务 控制台顶部搜索框输入 IoTDA → 进入"设备接入 IoTDA"控制台。首次进入会引导购买实例。
4
购买免费单元 总览 → 免费体验/购买实例：
  • 规格：标准版免费单元 S0（注意不是"基础版"！基础版是共享版，已不再推荐）
  • 区域：华北-北京四（cn-north-4）（本项目选的区域；哪个区域都行，但前后所有配置必须同区域）
  • 计费：免费（1000 设备 / 日 1 万条消息额度）
5
记下实例的接入地址 开通后进入实例的 总览 → 接入信息，能看到两个域名，都抄下来：
地址类型本项目实际值给谁用
设备侧（MQTT）71b55ab7e9.st1.iotda-device.cn-north-4.myhuaweicloud.com:8883小车端
应用侧（HTTPS）https://71b55ab7e9.st1.iotda-app.cn-north-4.myhuaweicloud.com业务后端
⚠️ 关键认知（403 事故的根源）应用侧有两个长得像的地址：通用地址 iotda.cn-north-4.myhuaweicloud.com（基础版用的）和实例专属地址 71b55ab7e9.st1.iotda-app...（标准版实例的）。标准版实例必须用专属地址，用错了怎么调都是 403。专属地址开头的数字串就是实例 ID，已在域名里，后面调 API 时不需要再传 instance_id 参数。
✅ 自检控制台"总览"能看到实例运行中，接入信息里能查到设备侧和应用侧两个地址。

1.3 创建产品 + 定义物模型

6
新建产品 实例内 产品 → 创建产品：
  • 产品名称：smart-car；协议：MQTT；数据格式：JSON
  • 设备类型：自定义（或从模板选）
  • 创建后系统分配产品ID（一串十六进制，本项目为 6ae440347f2e6c302fa846ee）
7
上传物模型 产品详情 → 功能定义 → 上传模型文件。IoTDA 只接受 zip 包，目录结构必须是： 
smart-car-model.zip
├── profile/devicetype-capability.json          ← 产品能力描述
└── service/service1/profile/servicetype-capability.json  ← 服务定义（属性/命令）
本项目物模型：服务 car，5 属性（x / y / heading / speed / battery）+ 5 命令（FORWARD / BACK / LEFT / RIGHT / STOP）。成品在 iot-stage/model/smart-car-model.zip。
⚠️ 坑：description 字符白名单模型文件里所有 description 字段有字符白名单校验：°（度符号）、全角冒号：等都会被拒（报 IOTDA.000006）。描述里只用中文、英文字母、数字和空格最稳。
✅ 自检产品详情"功能定义"里能看到 5 个属性和 5 个命令，没有红色报错。

1.4 注册设备（这台"小车"的出生证）

8
单个添加设备 设备 → 所有设备 → 注册设备：
  • 所属产品：smart-car
  • 设备标识码：car-001
  • 密钥方式：不填（让平台自动生成，即"一机一密"）
9
保存设备凭证（只显示这一次！） 注册成功弹窗会显示 设备ID 和 设备密钥（secret）：
  • 设备ID = 产品ID_设备标识码，如 6ae440347f2e6c302fa846ee_car_001
  • secret 是一串 32 位十六进制
关掉弹窗后 secret 不再完整显示。立刻抄下来（丢了只能重置密钥）。
✅ 自检设备列表出现 car-001，状态为 未激活（INACTIVE）——这是正常的，等小车端第一次连上云会自动变成"在线"。

1.5 创建 IAM 子用户并授权（给程序发"工牌"）

10
进入统一身份认证 IAM 控制台搜索 IAM → 进入"统一身份认证服务"。
11
创建用户 用户 → 创建用户：
  • 用户名：如 iot-aa
  • 凭证类型：勾选"访问密钥"（编程访问，给程序用）；需要登录控制台就同时勾"密码"
⚠️ 坑：凭证类型勾选创建时如果没勾"访问密钥"，用户创建出来就没有 AK/SK，得事后在"安全设置 → 访问密钥"里单独创建（也行，但新手容易找不到入口）。
12
加入用户组（授权） 创建流程下一步（或事后点"授权"）把用户加入用户组：
  • 图省事：admin 组（华为云管理员，全权限）——本项目 iot-aa 就是这样
  • 更规范：只建一个挂 IoTDA FullAccess 策略的组，把 IoT 用户放进去（最小权限原则）
13
下载 AK/SK 凭证文件（只显示这一次！） 用户创建成功会弹出 credentials.csv 下载按钮，内容形如： 
User Name,Access Key Id,Secret Access Key
iot-aa,HPUA****...,****mUMx...
SK 同样只显示这一次，CSV 丢了就得作废重建。也可以事后在 我的凭证 → 访问密钥 里为用户创建新密钥。
✅ 自检打开 我的凭证 页面（右上角头像菜单）：能看到"账号ID""IAM用户ID"；"项目列表"里能找到 cn-north-4 对应的项目ID——这就是后端要的 project_id。
🔎 记录页面一览我的凭证（右上角头像 → 我的凭证）是新手最重要的页面：账号ID、IAM用户ID、项目ID、访问密钥（AK/SK）全在这里。调 API 需要的三个 ID 类数据（账号ID / 用户ID / 项目ID）都能从此页复制。

二、核心配置管理

2.1 产品管理

操作入口要点
查看/修改物模型产品 → 功能定义 → 自定义功能页面可视化增删属性/命令，也可重新上传模型 zip 覆盖
查询产品ID设备 → 产品过滤；或产品详情产品ID 是设备ID 的前缀
在线调试设备详情 → 命令下发控制台可手动给设备发命令，验证物模型（注意：手动调试和脚本同时在线会互踢）

2.2 设备管理

操作入口要点
看设备在线状态设备 → 所有设备未激活（从未连过）/ 在线 / 离线。判定依据是 MQTT 长连接是否存活
重置设备密钥设备详情 → 安全 → 重置密钥secret 丢了用它；重置后旧密钥立刻失效
看设备影子设备详情 → 设备影子云端缓存的最后一次属性上报，设备离线也能查
删除设备设备列表 → 删除删除后设备ID 可重新注册；影子数据一起清空
⚠️ 互踢规则同一设备ID 只允许一条 MQTT 长连接。第二个实例（或控制台的"设备模拟器"、或另一台电脑跑同一脚本）连上去，旧连接会被踢下线。演示时确认只跑一份 car_mqtt_client.py。

2.3 IAM 用户与权限管理

操作入口要点
创建/停用/删除用户IAM → 用户停用后该用户的 AK/SK 和登录立即失效
调整权限用户 → 授权 / 用户组管理权限挂在用户组上，用户通过加入组获得权限
创建 AK/SK我的凭证 → 访问密钥
（或 IAM → 用户 → 安全设置）		每个用户最多 2 个有效 AK；删除即失效
改登录密码IAM → 用户 → 安全设置 → 修改密码子用户首次登录控制台会强制改密码
🔎 实测结论（本项目 4 账号对比）主账号、admin 子用户、普通 IoT 子用户，只要权限覆盖 IoTDA，调应用侧 API 都能通。教学环境用哪个都行；但 AK/SK 该用谁的是管理问题：建议日常用普通子用户的密钥，admin 密钥只在管理操作时用，主账号 AK/SK 尽量不落盘。

2.4 额度管理（免费实例的生命线）

资源免费额度超了会怎样本项目对策
设备数1000 台无法注册新设备一个班几十台绰绰有余
消息数每日 1 万条当日新消息被拒，次日恢复属性上报节奏降频：运动 5s/条、静止 60s/条（已写入 car_mqtt_client.py）。千万别按 TCP 阶段 100ms 一条的习惯来，那速率 1 台车几分钟烧完全天额度
查看用量IoTDA 控制台 → 总览 / 实例详情里有消息统计图表。课堂演示当天开课前先看一眼剩余额度。

cd iot-stage/server
D:\anaconda3\python.exe car_mqtt_client.py

  • 设备详情"最新上报"能看到 x/y/heading 等属性值 → 属性上报正常

curl http://127.0.0.1:8000/health  # → {"ok":true,"device_online":true}

4.3 完整验收序列（curl 即可，不需要 APP）

curl http://127.0.0.1:8000/status                          # 记下当前 y 值
curl -X POST http://127.0.0.1:8000/command \
     -H "Content-Type: application/json" \

curl http://127.0.0.1:8000/status                          # y 变了 → 闭环成功
curl -X POST http://127.0.0.1:8000/command \
     -H "Content-Type: application/json" -d "{\"cmd\":\"STOP\"}"

五、常见报错速查表

报错场景含义与解法
rc=4（MQTT）小车连云鉴权失败。按顺序查：①设备ID/secret 抄错没 ②HMAC 算法的密钥和内容顺序（密钥=时间戳，内容=secret）③时间戳必须是 UTC 且格式 YYYYMMDDHH
rc=5（MQTT）小车连云未授权。设备未在该实例注册，或产品归属错了
403 IOTDA.000021调应用侧 API"用户不存在或未订阅"——错误信息有误导性。实测三大真凶：①端点用了通用地址而非实例专属地址 ②SDK 没配衍生签名（with_derived_predicate）③请求带了多余的 instance_id。与账号权限基本无关（4 个账号实测都能通）
IOTDA.000006 上传模型失败物模型上传description 含白名单外字符（°、全角冒号等），或 zip 目录结构不对
IOTDA.000006 paras must not be null下发无参命令命令的 paras 必须传 {}，不能是 null
设备突然离线演示中途同设备ID 被另一处连接（控制台调试器/另一份脚本）踢下线，或当日消息额度耗尽
STOP 后 /status 的 speed 仍是旧值轮询状态设备影子按上报节奏刷新（静止 60s/条），不是 bug；等一个上报周期或看 commands.log 确认命令已执行
ImportError: huaweicloudsdk...跑 app.py用错了解释器。必须 D:\anaconda3\python.exe（3.10，SDK 装在它的用户目录），裸 python 是 3.13 没有这些包

六、安全与收尾管理

6.1 凭证管理纪律

  • 🔑 AK/SK、设备 secret 只存本机 config.json / 脚本常量，不进 Git 仓库、不发群、不进课件
  • SK 和 secret 只在创建时显示一次——养成"弹窗即抄录归档"的习惯
  • 课件/文档里截图注意打码（本手册所有密钥示例均为截断展示）

6.2 结课收尾清单

  • 设备：批量删除或停用（防学生课后再连）
  • IAM 子用户：停用（比删除温和，可恢复）
  • AK/SK：删除不再使用的密钥
  • 实例：免费单元不扣费，可保留供下学期复用；确认消息额度监控无人为异常
